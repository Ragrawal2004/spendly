This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Spendly is a Flask-based expense tracker, built incrementally as a step-by-step learning project. The codebase is intentionally scaffolded with placeholder routes and an empty database module — features are implemented one step at a time rather than all at once.

## Commands

The venv lives at `.venv/` (not `venv/` — note the `.gitignore` excludes `venv/`, which doesn't match the actual `.venv/` directory name).

The app needs PostgreSQL. One-time setup (the `spendly-pg` Docker container, then one database for the app and one for the tests):

```bash
docker start spendly-pg
docker exec spendly-pg psql -U postgres -d postgres -c "CREATE DATABASE spendly"
docker exec spendly-pg psql -U postgres -d postgres -c "CREATE DATABASE spendly_test"
```

Both `DATABASE_URL` (dbname `spendly`) and `SPENDLY_TEST_DATABASE_URL` (dbname `spendly_test`) are required and are exported in the shell profile, e.g. `postgresql://postgres:PASSWORD@localhost:5432/spendly`. Never print them or commit a real password.

```bash
# Install dependencies (venv activation doesn't persist across separate Bash calls,
# so either chain source+command, or call the venv binary directly)
.venv/bin/pip install -r requirements.txt

# Run the dev server (binds port 5001, not Flask's default 5000; needs DATABASE_URL)
.venv/bin/python3 app.py

# Same, with a fixed secret key so sessions survive the debug reloader
SPENDLY_SECRET_KEY=dev-only-value .venv/bin/python3 app.py

# Run tests (needs SPENDLY_TEST_DATABASE_URL; stops before any test unless its dbname is spendly_test)
.venv/bin/pytest
.venv/bin/pytest path/to/test_file.py::test_name   # single test
```

## Architecture

Flat, single-file Flask app — no blueprints, no app factory pattern. Everything routes from `app.py`.

- **`app.py`** — the only entry point. Each route either calls `render_template(...)` for built pages or returns a placeholder string for features not yet implemented (labeled with their build step, e.g. `"Edit expense — coming in Step 8"`). Runs on port 5001 in debug mode. Built so far:
  - `/register` — `clean_registration()` and `validate_registration()` helpers; POST creates the user and redirects to `/login?registered=1`; a duplicate email (`psycopg.errors.UniqueViolation` only) gives a 400 "An account with this email already exists." Signed-in users are redirected to `/profile`.
  - `/login` (Step 3, complete) — `clean_login()` reads the form (email stripped and lowercased, password untouched); `authenticate()` is the only credential check and makes exactly one `check_password_hash` call on every path (a dummy hash stands in for unknown emails and over-long input; a malformed stored hash counts as a failed check), so failures take the same time and give the same generic message ("Invalid email or password."; blank fields give a 400). Success clears the session, stores `user_id`, issues a fresh `csrf_token` and redirects to `/profile`. Signed-in users are redirected to `/profile`. The `GET` 200 pages of `/login` and `/register` are `no-store`.
  - `/logout` — `POST` only (`GET` gets Flask's 405), clears the session and redirects to `/`. The nav "Sign out" button is a small POST form.
  - `/profile` (Step 4, complete) — `GET` only, behind `@login_required`. Fetches `get_user_profile(uid)` for the signed-in user; if that returns `None` (user vanished mid-request) it clears the session and redirects to `/login`. Otherwise renders `profile.html` with the account card (name, email, "Member since" only when `created_at` parses), stat tiles (total, this month, expense count), the category breakdown with percentages, and the five most recent expenses (or a "No expenses yet." empty state). The response sets `Cache-Control: no-store` and the 200 path never writes the session. It reads only `g.current_user["id"]`, never a request parameter, so no one can view another user's page. The nav user name links here.
  - `/expenses/add` (Steps 6-7, complete) — both `GET` and `POST` are behind `@login_required`; `GET` renders `add_expense.html` through `render_expense_form(...)` (today's UTC date prefilled, the seven categories, `min`/`max` dates and `maxlength` from the validation constants) and sets `Cache-Control: no-store`. `clean_expense(form)` strips `amount`, `category`, `date` and `description`. `validate_expense(amount, category, date, description, today)` checks in this order and returns `(error, None)` on the first failure or `(None, values)`: amount (format, then `> 0`, then `<= MAX_AMOUNT`), category, date, description length, then description control characters. The amount must `fullmatch` `_AMOUNT_RE` (ASCII `[0-9]` only) and is a `Decimal`, never a `float`. The constants are `CATEGORIES` (the seven schema categories), `MAX_AMOUNT` (₹1,00,00,000), `MIN_EXPENSE_DATE` (1 January 2000) and `MAX_DESCRIPTION` (200). The date must `fullmatch` `_DATE_RE`, parse with `datetime.strptime(...)` and fall between `MIN_EXPENSE_DATE` and tomorrow in UTC (`today` is passed in, so the helper is pure). The description may be blank (stored as `NULL`) but is rejected if any character is Unicode category `Cc`; `Cf` characters are still stored (review flag R4 is closed: `/profile` wraps each description in `<bdi>`, so a direction override cannot reorder the rest of its row). An error re-renders the form with a `400` through `render_expense_form`, showing the message and the submitted values; Jinja autoescaping covers every value (no `|safe`, no `Markup`) and the response is `no-store`. Success calls `create_expense` and returns a `303` redirect to `/profile`; the success and `400` paths never write the session (the form's hidden token reuses the one already in the session). The owner is always `g.current_user["id"]`, never a form field. `psycopg.errors.ForeignKeyViolation` (the user vanished mid-request) clears the session and redirects to `/login`.
  - `login_required(view)` — the only signed-out gate: if `g.current_user` is falsy it redirects to `/login` (no `next` parameter, nothing read from the request), otherwise calls the view. Apply it below `@app.route(...)`.
  - Profile helpers (pure, unit tested without a request): `month_bounds(today)` returns ISO strings for the first day of this month and of next month (December rolls to January); `member_since(created_at)` turns a `datetime` (naive treated as UTC, aware converted to UTC) or a `"YYYY-MM-DD HH:MM:SS"` string into `"March 2026"`, or `None` for missing, malformed or any other input; `format_amount(value)` gives `₹12,345.60` and is also registered as the `format_amount` Jinja filter; `category_share(total, overall)` works in `Decimal` and gives a half-up rounded whole percentage, or `0` when `overall` is 0. The current month comes from `datetime.now(timezone.utc).date()`.
  - `resolve_secret_key(env)` and `session_cookie_secure(env)` — pure helpers that read the environment for the secret key and the cookie `Secure` flag.
- **Sessions** — the signed Flask cookie session holds `user_id` and `csrf_token` and is non-permanent (ends with the browser session). Cookies are `HttpOnly`, `SameSite=Lax`, and `Secure` in production. A `before_request` hook (`load_current_user`) is the only code that reads `session["user_id"]`: it sets `g.current_user` (a `get_user_by_id` row, or `None`) and clears the session if `user_id` is not an `int` or no longer matches a user. A context processor exposes it to templates as `current_user`. Routes check `g.current_user`, never the session. Known gaps, deliberately left: no rate limiting; only the `/expenses/<id>/edit` and `/expenses/<id>/delete` placeholder routes stay public until Steps 10-11 (the `"coming in Step 8"` and `"coming in Step 9"` strings in `app.py` are out of date and will be replaced in Steps 10 and 11).
- **CSRF** — one random token per session, kept in the session as `csrf_token`. `get_csrf_token()` creates it on first use and is exposed to templates as the `csrf_token()` global; every `POST` form carries it as a hidden `csrf_token` field. Pages with no form never create one. `login()` rotates it (the session is cleared, then a new token is issued) and `logout()` drops it with `session.clear()`. `check_csrf_token` is a global `before_request` hook registered **before** `load_current_user`; it checks only matched `POST`s (a `405` or `404` is left alone), reads only `request.form` (never `request.args` or headers), requires both values to be non-empty strings and compares them as UTF-8 bytes with `secrets.compare_digest`. A missing or wrong token gives a fixed plain-text `400` (`Invalid or missing form token. Reload the page and try again.`) that never touches the session, so it sets no cookie. `no_store(rv, status=200)` adds `Cache-Control: no-store`; `/login`, `/register` and `/expenses/add` use it because their pages carry a token. Tests send the token through `tests/helpers.py` (`csrf_token(client)` and `post_form(client, url, data)`). Mutating routes (edit and delete, Steps 10-11) must be POST-only forms carrying the token; the hook checks only POST.
- **Environment variables** — `SPENDLY_SECRET_KEY` signs the session cookie. If unset or empty, a random key is generated per process (fine for development, but sessions are lost on restart or debug reload). `SPENDLY_ENV=production` makes a missing key a startup `RuntimeError`, skips demo seeding and sets `Secure` on the cookie. `DATABASE_URL` is the PostgreSQL connection URL; if unset or empty, `resolve_database_url` raises a `RuntimeError` in every environment. `SPENDLY_TEST_DATABASE_URL` is read only by `tests/conftest.py`, which points `DATABASE_URL` at it. Never hard-code a key or a URL. `tests/conftest.py` sets a test key before `app` is imported, and the whole suite stops before any test if the test URL is missing, names a database other than `spendly_test`, or the server is unreachable. The autouse `isolated_db` fixture sets `lock_timeout = '5s'` and runs `DROP TABLE IF EXISTS expenses, users CASCADE` before every test; the `client` fixture then calls `init_db()` to recreate the tables. A test file that asserts empty tables must `import app` at module top, so `app`'s startup demo seed runs at collection time, before `isolated_db` drops the tables. Tests never touch `spendly` or `spendly.db`.
- **`database/db.py`** — all PostgreSQL access lives here (raw `psycopg` 3, `%s` placeholders). `resolve_database_url(env)` returns `DATABASE_URL` or raises `RuntimeError` with a fixed message that never contains an env value. `get_db()` opens a connection with `row_factory=dict_row` and `autocommit=True`, so every statement commits by itself and rows are plain `dict`s; multi-statement writes use `with closing(get_db()) as conn, conn.transaction():`. Never use `with conn:` (it closes the connection in psycopg 3). `init_db()` (creates tables and indexes with `IF NOT EXISTS` in one transaction), `seed_db()` (demo data for development, including the `demo@spendly.com` / `demo123` user; `INSERT ... ON CONFLICT (email) DO NOTHING RETURNING id` and the expense inserts share one `conn.transaction()`, so seeding is idempotent and all-or-nothing), `create_user()` (parameterised `INSERT ... RETURNING id`, returns the `int` id; lets `psycopg.errors.UniqueViolation` propagate so the route can report a duplicate email), `create_expense(user_id, amount, category, date, description)` (parameterised `INSERT ... RETURNING id`, returns the `int` id; does no validation, so `psycopg.errors.CheckViolation` and `psycopg.errors.ForeignKeyViolation` propagate to the caller), `get_user_by_email()` (returns `id, name, email, password_hash` or `None`; used only for login), `get_user_by_id()` (returns `id, name, email`, no hash, or `None`), and the profile reads: `get_user_profile(user_id)` (`id, name, email, created_at`, no hash, or `None`), `get_expense_summary(user_id, month_start, next_month_start)` (one row of `total`, `count`, `month_total`, zeros when there are no expenses; the month is `month_start <= date < next_month_start`), `get_category_totals(user_id)` (`category, total, count`, ordered by total descending then category) and `get_recent_expenses(user_id, limit=5)` (`id, amount, category, date, description`, newest date first, ties by higher `id`). Return types: single-row reads give a `dict` or `None`, list reads a `list[dict]`; `amount` and the totals are `Decimal` (`NUMERIC(12,2)`), `date` is `datetime.date`, `created_at` is a timezone-aware `datetime` (`TIMESTAMPTZ`), `count` is `int`. The schema enforces the rules: `amount > 0`, the seven categories, a non-blank name, real calendar dates, and a lowercase email via the `users_email_lowercase` CHECK (the reason `app.py` strips and lowercases emails before every save or lookup). Every query filters by `user_id` and does no rounding; formatting happens in `app.py`. Routes in `app.py` call these rather than touching raw SQL.
- **`templates/`** — server-rendered Jinja2 templates. `base.html` is the shared shell (nav, footer, font/CSS/JS includes); page templates (`landing.html`, `login.html`, `register.html`, `profile.html`, `add_expense.html`, `terms.html`, `privacy.html`) extend it via `{% block content %}`.
- **`static/`** — assets served directly via `url_for('static', filename=...)`, referenced from `base.html` so they're shared across all pages: one CSS file (`css/style.css`) and one JS file (`js/main.js`, currently empty — students add JS here as features are built).

No ORM — raw `psycopg` access through `database/db.py`.
